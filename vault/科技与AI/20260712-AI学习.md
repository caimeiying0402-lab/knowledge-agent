## 角色
- 你是一名专业的票据智能审核引擎，专注于处理员工报销审核场景。

## 目标
- 基于原始票据图片、审核规则的描述以及待审核表单，判定用户的报销费用是否可审批通过。
- 提供详细的审核结果，包括规则验证的过程和判定依据。

## 技能
- 审核规则理解：能够准确解析规则名称、条件表达式、错误级别和依赖字段。
- 数据验证与逻辑判断：能够执行数据完整性检查、条件表达式解析，并根据票据数据进行验证。
- 系统变量处理：能够在条件表达式中引用系统变量，例如当前时间等。
- 多票场景处理：能够处理多个票据并结合规则进行审核。

### 4. 审核规则
```
rule1: 合理性校验(reimbursement policy)
支持报销其他团建可能产生的费用：
1. 团建产生的住宿费、交通费、餐饮和酒水等。
2. 与团建活动相关的合理费用如门票、服务费、物料、道具、礼品
3. KTV、按摩、美甲、泡温泉、活动门票等

明确不允许报销：
    1. 现金及现金等价物，如黄金、礼品卡（除非能明确看到礼品卡用于餐饮兑换，否则需获得建政策负责人批准）、代金券等；
    2. 奢侈品品牌消费，如爱马仕、香奈儿、LV
rule2: 完整性校验(invoice rules)
票据明确显示了日期（如支付日期、交易日期、账单日期等），总金额，消费明细则校验通过，否则校验不通过。
结果严格按照描述执行，不要根据表单信息反推票据信息。

rule3: 日期一致性校验(date consistent)
要求票据日期（任意类型日期）与费用行的费用发生日期date。仅做日期匹配，不需要考虑票据的HH:mm:ss。
如果票据没有体现日期，则不做日期一致性校验。

rule4: 币种一致性校验(currency consistent)
要求票据识别到的币种和员工费用行填写的消费币种currency一致。如果是多票的情况，员工填写的currency和任一票据的币种一致即可。

rule5: 金额检查(amount consistent)
费用行的消费币种金额currencyAmount不得超过票据总金额。如果票据单独体现了小费或者税费，票据总金额需包含小费和税费。如果是多张发票的情况，需要根据实际情况判断如何处理多张票据的金额。
    - ① 通常提供的是多次消费的凭证，则需要对多张发票的金额进行求和。
    - ② 如果是同一次消费有多张票据，则选取金额较高的作为可报销金额。


注意：
    - 1. 注意区分是千分位还是小数位：比如 163.500 ，小数点后超过2位，说明这里是千分位，而不是小数位，因为金2. 额小数位只会是 2 位，因此金额为 163500
    - 2. 金额数值相等即可，不要求精度完全一致。如票据金额199.50 与 表单金额199.5，认为金额相等
    - 3. 如果票据包含税费或者小费，注意提取的票据金额为总金额。如票据Total=$204.75，tip=$40.95，total paid=$245.70,应提取total paid=$245.70作为票据金额
    - 4. 规则判定结果严格按照以上描述执行,不要做常理性推测，也不要做假设。
    - 5. 结果严格按照描述执行,不要根据表单信息反推票据信息。
    - 6. 如果上下文不明确,则优先按不通过判定
    - 7. 以上所有规则均校验通过,则机审审核结果audit_result=true。有任意一条规则不通过,则审核结果audit_result=false
```

## 工作流程
1. **规则理解**：
   - 解析输入的审核规则，包括规则名称、条件表达式、错误级别以及依赖字段。
   - 确保每条规则的含义和适用范围被正确理解。

2. **规则验证**：
   - **数据完整性检查**：确认所有依赖字段是否存在于票据数据中。
   - **逻辑判断**：使用JavaScript语法解析条件表达式，并结合票据数据进行验证。
   - **系统变量注入**：在条件表达式中引用系统变量（如用户填写费用发生日期、报销金额）以完成验证。
   - **多票场景处理**：合并票据信息并进行整体校验。

3. **结果生成**：
   - 输出单据的机审结果，如机审不通过需明确不通过原因
   - 针对每条规则生成结果对象，包含以下信息：
     - 是否通过验证。
     - 详细的判定依据。
     - 规则名称。
   - 如果上下文不明确，则优先按不通过判定。

4. **特殊处理**：
   - 对数值型字段执行四位小数精度的比对。
   - 对缺失的依赖字段自动标记为"N/A"。
   - 过滤票据内容中金额为负数的费用，不纳入统计和分析。

## 约束
- 必须处理所有输入的票据类型和数据。
- 所有规则必须被验证并输出结果。
- 各规则之间的判断需独立，互不影响。
- 对票据数据的处理需严格遵守审核规则。

## 输出格式
输出应为JSON字符串，包含以下键值对：
- `thought`: String，Step by step展示详细的思考判断过程，包含逻辑递进和验证步骤。
- `output`: JSON, 包含以下键值对：
    - `audit_result`: Boolean，表示是否机审通过。true-审核通过、false-审核不通过
    - `failed_reason`: [String], 校验不通过的规则id
    - `list`: [JSON], json array，json包含以下键值对
        - `rule_id`: String，规则唯一标识。
        - `rule_name`: String，规则名称。
        - `passed`: Boolean，表示是否通过规则验证。true-校验通过、false-校验不通过
        - `reason`: Multilingual，json array，详细的判定依据。
            - `zh_CN`: String，中文判断依据。
            - `en_US`: String，英文判断依据。
        - `failed_field`: [String]，未通过时标记的问题字段。

机器学习VS深度学习
（传统）机器学习 ≈ 让计算机从数据中学习规律，而不是靠人写固定规则。
流程：原始数据 → 人工特征提取 → 特征选择 → 模型训练 → 预测。
适用于：数据量小（小于1W）&解释性强（医疗/金融风控）&表格数据（结构化）或简单分类&人工做特征工程（耗时）&训练时间短&CPU&成本低
例：银行判断是否批贷/房价预测（少量数据）/预测某设备是否故障/电商早期用户分类/用问卷数据预测消费行为/特征含义明确的Excel / CSV 表格数据
深度学习 ≈ 机器学习的一种，使用多层神经网络自动提取特征。
机器学习的一个子集 + 多层神经网络 + 自动特征提取。「深度」指的是神经网络的层数。
流程：原始数据（像素/文本）→ 多层神经网络（自动提取特征）→ 预测；
适用于：数据量大（大于1W）&不强调解释性&表格数据（结构化）/图像/语音/文本/复杂感知任务（人脸识别、物体检测）&无需做特征工程（自动）&训练时间长&GPU&成本高
例：人脸识别/语音助手（你说它写）/大语言模型（GenAI）/自动驾驶（识别行人、车道）/医疗影像（X光、CT找病灶）/特征海量且稀疏或特征之间有深层非线性交互的Excel / CSV 表格数据

核心架构

现代 GenAI 主流：Decoder-Only + 自回归生成

内部处理机制
tokenization (prompt文本输入 → Token 序列)
embedding table(Token 序列→ Embedding 向量；vocabulary->参数矩阵)
Transformer 层层计算（自注意力）
deep learning（深入学习）/neutral network：多层layer：将输入/上一层 layer产出的Token embedding向量，考虑上下文，输出为另一层contextualized embedding向量，或称之为（hidden/latent representation）向量
每层layer（基于transformer模型）
self-attention layer：基于输入的Token embedding，通过逐一计算相关度的方式，寻找prompt中会影响当前Token embedding的token，将以上信息结合起来
计算相关度，确定关联性：
通过计算 「Query（查询）」 和 「Key（键）」 的点积（dot product）来打分。
Query（查询）-W_Q矩阵：谁在问？当前正在处理的 token 发出的「查询」。例： 当前 token 是「果」，那「果」会发出一个 Query：「喂，前面的词，谁和我关系最大？」
Key（键）-W_K矩阵：谁被问？每个前面的 token 都自带一个 Key
Dot Product（点积）：把 Query 向量和 Key 向量做点积。点积值越大，表示 Query 和 Key 越相似。
Value-W_V矩阵：匹配度结果。两个向量方向越一致，点积越大。方向越相反，点积越小（负值）。方向垂直，点积为 0。
multihead attention：模型能从多个不同角度、不同关系维度来理解语言，而不是只看单一的角度。
将以上信息结合起来
基于W_V矩阵结果的Value加总。
Feed-forward layer（FFN，前馈网络）：给每个 token 一次「独立思考」的机会，让它自己消化一下注意力层从其他词那里收集来的信息。
用处：独立处理——Token embedding拿着这些收集到的信息，自己再做一次深度思考。
过程：升维（Expand）；2. 非线性（激活函数如ReLU / GELU）；3. 降维（Project back） 
FFN 层存储了模型的“事实知识”和“模式记忆”。负责独立计算、存储事实信息、非线性变换
多层layer 会考虑上下文：“苹果”在Token embedding中为相同token；考虑上下文（吃苹果/苹果手机）后，会变成不同的contextualized embedding
向量空间：
向量（Vector）：是一列有顺序的数字，用来描述一个“点”在空间中的位置。在 LLM 里，一个词 → 被表示成一个 4096 维（高维）的向量，4096 维向量 [0.1, -0.5, ..., 0.3]：在 4096 维空间中的一个点
矩阵（Matrix）：是向量的“容器”或“函数”，核心作用是做线性变换（linear transformation）。
一个矩阵可以看作一堆向量排在一起（比如词表矩阵：128256 个词 × 4096 维）。矩阵 × 向量 = 另一个向量（这就是线性变换）。
在 LLM 里：
Embedding 矩阵[词表大小, 向量维度]：一个巨大的“字典”，存储所有词的向量；特定方向有特定含义（例如：特定方向代表中文/英文）；语义相同的词放在空间的相近位置
权重矩阵[输入维度, 输出维度]：对向量进行旋转、缩放、平移的操作器。每一层layer的作用，在几何上，是在 4096 维空间中，把一个点移动到另一个点。
LM Head 矩阵：将模型内部的连续向量（4096 维），加工为词表里每个离散 Token ID的概率。
为什么向量可以做语义运算？——“方向”（Direction）可以代表“意义”

标量

你的身高：175 cm；一个苹果的价格：5元。

损失函数的值、学习率、模型中的一个参数（如偏置bias）。

向量

一串有序排列的数字。

购物清单：[苹果, 香蕉, 橙子] = [5元, 3元, 4元]；或是一个人的身高、体重、年龄。

一切的基础。一个单词、一张图片的一行、一个数据样本，都表示为一个向量。

矩阵

一张由数字填满的表格（二维数组）。

一张Excel表格，行是用户，列是评分；或是一张黑白照片的像素网格。

神经网络的核心。每一层神经网络的权重就是一个矩阵，负责把输入的向量“变换”成输出的向量。

张量

向量的超级升级版（多维数组）。

一个魔方（三维）；一段彩色视频（四维：高度、宽度、颜色通道、时间）。

深度学习的数据容器。彩色图片是三维张量（长、宽、RGB），视频是四维，大模型内部处理的也是超高维张量。

世界是不确定的。概率统计就是教AI在信息不全时，如何理性地“猜”答案，并且告诉你有几成把握。

正态分布

中间多，两头少，对称的“钟形曲线”。自然界最常见。

人类的身高、智商、考试分数。大部分人是平均身高，特别高和特别矮的极少。

无处不在。模型参数初始化、误差分布、潜在空间假设。几乎所有模型的优化目标都假设误差服从正态分布。

幂律分布

少数东西极大，多数东西极小（长尾）。

微博大V的粉丝数（少数人几千万粉丝，多数人几百个）、单词使用频率。

自然语言处理。Zipf定律：最常出现的词（的、了、一）占了绝大多数文本。

均匀分布

在一个范围内，可能性均等。

一个完美的骰子（1-6点概率均等）；随机数生成器。

随机初始化、Dropout正则化、在强化学习中做随机探索（ε-greedy）。

指数分布

描述等待时间，事件发生越往后概率越低。

地震发生的间隔时间；公交车到站的等待时间。

生存分析（预测用户流失时间）、排队论（优化系统性能）、强化学习中描述奖励的时间衰减。

t分布、F分布、χ²分布

由正态分布派生出来的分布，用于小样本统计推断。

t分布（小样本时，用样本方差代替总体方差后的修正）；χ²分布（衡量实际与期望的差距）。

决策边界
当华为 Mate 降价到 5000 元的时候我就打算购买，那这种情况下我的决策边界就是 5000 元，因为大于 5000 元的时候我不会购买，只有小于 5000 元时我会选择购买。
决策边界是判断一个算法是线性还是非线性最重要的标准。线性回归和逻辑回归这样的线性算法，它们的决策边界也是线性的，长得像线条或者平面，而对于决策树和随机森林这样的非线性算法，它们的决策边界也是非线性是一条曲线。
一般来说决策边界曲线越陡峭，模型在训练集上的准确率越高，但陡峭的决策边界可能会让模型对未知数据的预测结果不稳定（会过拟合）。
模型训练的目标：在已知的用户中用分类算法找到一个决策边界，然后再用决策边界把未知新用户快速划分成流失用户或者是非流失用户。
找到合适的决策边界：拟合能力与泛化能力的平衡点。找到在已知数据和未知数据表现都很好的最优模型。拟合能力代表模型在已知数据上表现得好坏，泛化能力代表模型在未知数据上表现得好坏。它们之间的平衡点，就是我们通过不断地训练和验证找到的模型参数的最优解，因此，这个最优解绘制出来的决策边界就具有最好的拟合和泛化能力。这是模型训练中“最优”的意思，也是模型训练的核心目标，我们一定要记住。
一般情况下，算法工程师会通过交叉验证（Cross Validation）的方式，找到模型参数的最优解。
模型验证

模型验证主要是对待验证数据上的表现效果进行验证，一般是通过模型的性能指标和稳定性指标来评估。
性能：模型预测的效果。评估方式：分类模型评估和回归模型评估 。
分类模型（离散值）：评估指标为 召回率、F1、KS、AUC 
回归模型（连续值）：评估指标为 方差和 MSE
稳定性：模型性能（也就是模型的效果）可以持续多久
PSI 指标：PSI > 0.2，稳定性太差，说明算法同学的工作交付不达标。
模型融合

同时训练多个模型，再通过模型集成的方式把这些模型合并在一起，从而提升模型的准确率。简单来说，就是用多个模型的组合来改善整体的表现。
例：银行数据强相关，机器学习；互联网高维稀疏，深度学习
分类模型（离散值）：Blending Stacking  Bagging Boosting 投票法
回归模型（连续值）：算数平均或加权平均的方法来融合
模型部署

部署到线上。算法模型基本也是部署成独立的服务，然后暴露一个 HTTP API 给工程团队进行调用，这样可以解耦相互之间的工作依赖。实时响应的 API 接口或离线任务。简单的机器学习模型一般通过 Flask 来实现模型的部署，深度学习模型一般会选 TensorFlow Serving 来实现模型部署。

AI背景下，职业能力分层。职业能力中的信息获取、知识记忆、流程执行可以逐步由AI替代，回答问题的价值走低；而经验判断、决策承担并不，发现问题的价值并未受到影响。也就是说，AI的能力来自知识，长期经验下形成的模式识别、重新定义问题的能力是依然珍贵的。当然，很多低价值工作其实承担着积累经验的作用，可以帮人建立案例库、异常感知、风险直觉，形成所谓的sense。就好比说开车技术是至少开到六万公里，才来谈的东西，在那之前不存在技术，只有摸索。AI时代最大的风险不是不会用AI，而是跳过经验形成过程。AI让人以为获得信息就是获得理解。AI能突破、进入、发挥作用的地点，是执行效率已经成为瓶颈的地方，作用很小的是判断力成为瓶颈的地方。
AI正在降低获取答案的门槛，但职业竞争力越来越取决于发现问题、识别风险和形成判断的能力。很多看似可以被AI替代的工作，其真正价值并不在产出本身，而在于它为人提供了大量接触真实案例、建立经验模型和形成职业sense的机会。知识可以被快速获取，判断力仍然需要通过长期反馈循环逐步形成。在标准场景下，AI越来越强；在非标准场景下，人类的价值越来越集中于异常识别、风险判断和责任承担。而这些能力的形成，往往依赖大量真实经历，而不是大量信息。知识获取的速度被AI大幅压缩，但从“知道”到“理解”，从“理解”到“判断”，依然需要自己的六万公里。
