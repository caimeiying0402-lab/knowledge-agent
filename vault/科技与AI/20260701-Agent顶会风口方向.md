# Agent顶会风口方向

下一个顶会风口在哪？ - 小红书

很难说有一个公认的"下一个 Harness"，但如果要押注，我觉得几个方向值得盯： 	 记忆与状态。 现在 agent 每次基本是从零开始，上下文塞满就丢。怎么让它跨会话、跨任务真正"记住"东西——而不是把整个历史硬塞进 context——是个明显的痛点。这不只是塞进向量库那么简单，涉及什么该记、什么该忘、怎么取。 	 多 agent 协作的工程化。 现在多 agent 大多还停留在"看着挺酷"的 demo阶段，真正可靠地编排、让它们分工不打架、出错能恢复,还很糙。谁能把这块做得像写普通分布式系统一样可控，会很有价值。 	 评测和可靠性。 这个很关键。agent 行为难复现、难回归测试,出了问题不知道哪一步坏的。配套的trace、eval、回放工具会跟着起来——有点像当年测试框架、CI 之于普通软件。各大厂现在都在构建可观测性能力 	 环境与权限边界。 agent 要真正动手干活（跑命令、改文件、调外部服务），沙箱、权限、审计这套东西必须跟上,否则没人敢放它进生产。 	 个人感觉，记忆和可靠性工程这两块最可能先热起来——因为它们是"让 agent 从玩具变成能托付的东西"绕不开的坎。其余的更像是会持续演进，而不是某天突然引爆。 #小红书科技AMA #agent #大模型 #计算机 #大模型应用 #计算机专业 #ai #大模型学习

下一个顶会风口在哪？
很难说有一个公认的"下一个 Harness"，但如果要押注，我觉得几个方向值得盯：
	
记忆与状态。
现在 agent 每次基本是从零开始，上下文塞满就丢。怎么让它跨会话、跨任务真正"记住"东西——而不是把整个历史硬塞进 context——是个明显的痛点。这不只是塞进向量库那么简单，涉及什么该记、什么该忘、怎么取。
	
多 agent 协作的工程化。
现在多 agent 大多还停留在"看着挺酷"的 demo阶段，真正可靠地编排、让它们分工不打架、出错能恢复,还很糙。谁能把这块做得像写普通分布式系统一样可控，会很有价值。
	
评测和可靠性。
这个很关键。agent 行为难复现、难回归测试,出了问题不知道哪一步坏的。配套的trace、eval、回放工具会跟着起来——有点像当年测试框架、CI 之于普通软件。各大厂现在都在构建可观测性能力
	
环境与权限边界。
agent 要真正动手干活（跑命令、改文件、调外部服务），沙箱、权限、审计这套东西必须跟上,否则没人敢放它进生产。
	
个人感觉，记忆和可靠性工程这两块最可能先热起来——因为它们是"让 agent 从玩具变成能托付的东西"绕不开的坎。其余的更像是会持续演进，而不是某天突然引爆。
