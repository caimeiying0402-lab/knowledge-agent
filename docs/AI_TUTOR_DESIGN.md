## 背景

用户希望构建一个 AI 导师 agent 系统：

- 时常有学习诉求（ACP 认证、投资、亲密关系……）
- 希望"按需启动"不同导师，每个导师基于指定人设/知识跟用户对话
- 资料来源：小红书博主公开发布内容、官方课程、私域文档
- 长期目标：沉淀为"个人人生大学档案"

---

## 用户 AIOS 背景（关键工程前提）

用户已在搭建个人 AIOS 系统，包含：

1. **知识采集**：爬虫 / 企业微信 / Cloudflare + 本地 ETL / 飞书多维表 → GitHub 知识库
2. **找工作**：招聘爬虫 + 本地简历知识库 + 邮件/本地推送 + 招呼/简历/面试辅导
3. **知识推荐**：GitHub 知识库 + 用户兴趣分析 + 微信/邮箱触达
4. **AI 导师**（新模块）：复用 GitHub 知识库 + 个人网页入口

**关键约束**：导师不是独立系统，是 AIOS 的一个模块，复用底层能力

- 个人网页 = AIOS 统一入口，导师是其中 tab
- L1-L4 数据治理复用 GitHub 业务仓库（frontmatter 标注）
- 短期：Cloudflare Tunnel 暴露家里电脑；晚上回家拉取到 GitHub
- 长期：迁移到 2G 阿里云服务器（SaaS）
- 现有模型基础设施：CC Switch（assistant.dobest.com / 8001/route / 8090/v1）

## 时间轴 / 问答要点

### 维度 1：架构形态

- **Q1 单 Agent vs 多 Agent vs 混合**
  - A: 单 Agent 切换人设 / B: 多 Agent 并存 / **C: 主控 dispatcher + 专家池（已选）**
  - **决策：C**。理由——"按需启动"天然是路由问题；强人设导师必须独立，否则串味

### 维度 2：知识注入策略

- **Q2 资料怎么喂**：**方案 4：混合（已选）**
  - ACP 类（资料硬核）→ 手动喂料
  - 小红书博主类（要风格）→ 半自动抓取（影刀 RAP）
  - 通识类 → 提示词驱动 + 通用知识
- 用户确认能接受前期准备成本
- **Q-a skill 蒸馏链路**：抓资料 → 蒸馏人设（以博主口吻写自我分析）→ 注入导师 agent → 持续对话
  - 与"模板+微调"高度兼容

### 维度 3：交互产出

- **Q3 导师产出什么**：**C：对话 + 进度追踪 + 计划（已选）**
  - 新增：**跨导师汇总 → 个人"人生大学档案"**（由主控统一汇总）

### 维度 4：能力边界

- **Q4 导师边界**：**D：边界由主控 dispatcher 判定（已选）**
  - 人生大学档案由主控统一汇总（已选）
  - **Q-b 导师是否 agent 做事**：默认"只指导"，但留接口可挂工具
  - **Q-d 多导师群聊**：完全可做，机制 = 轮流发言 + 冲突显式 + 决策权在用户
- **Q6' 综合决策**：
  - **方案 2：顾问 + 低风险工具（已选）**
  - 投资 line 提醒 = 提醒不交易
  - 多导师群聊保留

### 维度 5：生命周期模型

- **Q5 导师长聘 vs 项目制**：**C：长聘 + 项目分层（已选）**
  - 模型：
    - **导师（Mentor）**：长聘身份，拥有人设、知识库、与用户的长期关系记忆
    - **学习项目（Learning Project）**：在某个导师下创建，有目标、起止时间、进度、产物
  - 人生大学档案以"学习项目"为单元归档，跨项目"成长曲线"由主控汇总

### 维度 6：差异化定位

- **Q-c 与市面 agent 差异化**：5 个维度同时差异化
  - 专家来源（用户自建）/ 知识库（用户指定）/ 人设（模拟具体人）/ 长期关系（有记忆）/ 跨场景串联（人生大学档案）
  - 代价：需自建，开箱即用体验弱

### 维度 7：长期记忆与数据治理

- **数据底座**：用户 GitHub 仓库（业务知识库，AI 可读，目录为业务驱动，不能简单按分级重构）
- **Q7 决策：方案 B（frontmatter 标注）**
  - 所有未标注文件默认 L2
  - 导师学习记录默认 L3
  - 其他分级 = 人工标注（frontmatter）
- **L1-L4 开放权限分级体系**（用户定义，非敏感度维度）：

| 级别 | 命名 | 谁能读 | 对外接口/互联网 | 默认归属 |
|------|------|--------|-----------------|----------|
| L1 | 全开放 | 任何导师 + 外部接口 + 互联网 | 允许 | 无（需人工标注） |
| L2 | 用户内部 | 任何导师 | 需对话内询问 | **默认（所有未标注文件）** |
| L3 | 单导师 | 仅该导师 + 总控 | 需对话内询问 | 导师学习记录 |
| L4 | 单次对话 | 仅当次对话 | 需对话内询问 | 无（需人工标注） |

- **三项澄清已确认**：
  - 主控 dispatcher 可读全部级别（用于跨导师汇总，如人生大学档案）
  - 对外动作（搜索/发邮件/调用外部 API）需对话内询问用户
  - L4 = 单次对话临时数据，对话结束可升级到 L3 永久存储或丢弃

### 维度 8：对话介质与网络

- **Q8 对话介质**：个人网页（已选）
- **Q8.5 网站与 GitHub 同步**：
  - 短期：Cloudflare Tunnel（家里电脑跑服务，Cloudflare 暴露成个人域名）
  - 长期：迁移到 2G 阿里云服务器（SaaS）
  - 关键澄清：Cloudflare Tunnel ≠ Cloudflare Pages；Tunnel 支持动态服务
- **Q10 网络可行性**：C - 先做功能，云端留 fallback；不预设公司网络策略

### 维度 9：AIOS 整合

- **Q9 整合深度**：B - 个人网页 tab + 后端可拆分

### 维度 10：模型路由

- **Q9.1 模型来源**：A - 全部走 CC Switch
- **Q9.2 导师间是否共用模型**：A - 共用
- **Q9.3 主控/专家区分模型**：先统一模型（开发阶段优先效果）
  - 后续如需差异化：CC Switch 可按请求头 / 路径 / 端口路由

### 维度 11：成本治理

- **Q10 决策**：先不管（开发阶段优先）
- 稳定使用后预估：月成本 ¥50-200（vs 真人私教 ¥500-5000/月）

### 维度 12：成果落点

- **Q11 决策：A - 落回 GitHub 仓库**
  - 理由：与知识库统一；可版本管理；可复用 RAG
  - 个人网页只读 GitHub，不存私货
  - 写入延迟由"晚上定时拉取"机制解决

### 维度 13：MVP 优先

- **Q12 决策：A - 单导师对话**（最小闭环，最快验证）
- **Q13 决策：δ - ACP 资料源 = α 官方文档 + β 题库/错题本混合**
  - 跳过 γ 课程视频转写（付费课程版权风险）
  - α 验证"硬核静态资料"注入
  - β 验证"测验/进度"链路

## 待决策 / 方案细化

### 1. 主控 Dispatcher 的"智能"程度

初步方向：规则路由 + 兜底 LLM + 用户信息总结

### 2. "导师长聘 + 项目分层"的记忆机制

- 导师级记忆 = 只存用户画像（性格、偏好、沟通风格）
- 项目级记忆 = 存事实性进度（看了什么资料、做对/做错哪些题、当前卡点）
- 检索时：项目记忆优先，导师级记忆做上下文补充

### 3. "人生大学档案"的写入时机和触发者

- **项目维度**：每次对话结束时，由当前导师生成一份 `project_update.md`（增量），包含"今天学了什么、卡在哪、下一步建议"，落回 GitHub 的项目子目录
- **全局维度**：主控每周一次（或项目结项时）扫描所有项目更新，生成一份 `weekly_summary.md`，跨项目汇总

### 4. 用户纠错机制（网页端）

- 网页上增加一个"这条回复有问题"按钮，点击后弹出框让用户写纠错备注
- 后台生成一个 `corrections/{conversation_id}.md` 落回 GitHub
- 不影响"只读"原则（网页只发起写操作到指定目录，不修改已有文件），但能回收纠错数据
